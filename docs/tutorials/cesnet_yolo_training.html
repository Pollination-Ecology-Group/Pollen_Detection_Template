General YOLO Training on CESNET Kubernetes (KáS)

A guide to running general YOLO training using CESNET MetaCentrum KáS (Kubernetes as a Service) with an academic identity.

This guide explains how your colleague can adapt the pipeline to run general YOLOv8 training (not limited to pollen detection) on the CESNET infrastructure.

1 1. Prerequisites

Before starting, ensure you have: - Academic Identity (eduID.cz): Used to log into CESNET services. - CESNET MetaCentrum KáS Access: You need an active project in the CESNET Kubernetes (Rancher) environment. - S3 Object Storage: Access to CESNET Object Storage (e.g., s3.cl4.du.cesnet.cz) to store training datasets and save trained models.

2 2. Accessing Kubernetes (KáS)

  1. Log into the CESNET Rancher UI using your academic identity.
  2. Select or create your Project/Namespace (e.g., yolo-training-ns).
  3. Click on your cluster and download the KubeConfig file.
  4. Save this file as kubeconfig.yaml in the root folder of this repository.

[!TIP] The deployment scripts (like deploy_train.sh) automatically check for a ./kubeconfig.yaml file in the current directory, so you don’t need to manually configure export KUBECONFIG.

3 3. Setting Up Secrets

Your training pod needs access to S3 to download the dataset and upload the final model.

First, create a Kubernetes secret for your S3 credentials in your namespace. You can run this command locally (ensure kubectl points to your CESNET cluster):

# Replace YOUR_NAMESPACE with the namespace you created in Rancher
kubectl create secret generic s3-credentials \
  --from-literal=access-key='YOUR_S3_ACCESS_KEY' \
  --from-literal=secret-key='YOUR_S3_SECRET_KEY' \
  -n YOUR_NAMESPACE

(Optional) If you use email notifications upon training completion:

kubectl create secret generic email-credentials \
  --from-literal=GMAIL_APP_PASSWORD='YOUR_APP_PASSWORD' \
  -n YOUR_NAMESPACE

4 4. Preparing the Dataset on S3

Upload your YOLO-formatted dataset (images and labels) to your CESNET S3 bucket.

Next, modify k8s/pollen-general-train-job.yaml to point to your specific dataset:

  1. Update the Namespace: Change namespace: stenc-ns to your namespace.
  2. Update Environment Variables:
env:
  - name: S3_ENDPOINT
    value: "https://s3.cl4.du.cesnet.cz" # Or your specific S3 endpoint
  - name: S3_BUCKET
    value: "your-bucket-name"
  1. Update S3 Sync Paths: Under the command section in the YAML, change the aws s3 sync commands to download your data instead of the pollen data:
# Example: Downloading your general YOLO dataset
aws --endpoint-url "$S3_ENDPOINT" s3 sync "s3://$S3_BUCKET/Path/To/Your/Dataset/" /app/Dataset/ --no-verify-ssl

5 5. Adjusting the Training Script

The training is handled by src/train_general.py. If your dataset path or training parameters differ, make sure train_general.py and the environment variables exported in pollen-general-train-job.yaml match.

Example update in k8s/pollen-general-train-job.yaml:

export DATASET_ROOT=/app/Dataset
export MODEL_DIR=/app/models/my_yolo_model/
python3 /scripts/train_general.py

6 6. Launching the Training Job

The pipeline uses ttl.sh, an anonymous, ephemeral Docker registry. This allows you to build and push Docker images directly from your local machine to the CESNET cluster without needing to set up a private Docker registry.

Update deploy_train.sh to point to your namespace by changing NAMESPACE="stenc-ns" to NAMESPACE="YOUR_NAMESPACE".

Deploy the training job:

./deploy_train.sh

7 7. Monitoring and Retrieving Results

Monitor the training progress via the Rancher UI or CLI:

kubectl logs -f pod/pollen-train-general -n YOUR_NAMESPACE

Once the training finishes, the script uses s5cmd to automatically sync the best model weights back to your S3 bucket.

# Look for this in the YAML command block to see where it uploads
s5cmd --endpoint-url "$S3_ENDPOINT" --no-verify-ssl sync "/app/models/my_yolo_model/*" "s3://$S3_BUCKET/Path/To/Output/"

8 Alternative: Training Locally (On Your Own Computer)

If you do not want to use CESNET Kubernetes or S3 and just want to run the training pipeline directly on your own computer (assuming you have a local GPU and Python installed), you can bypass the K8s configuration entirely.

  1. Install Dependencies: Make sure you have Ultralytics and other required libraries installed in your local environment.

    pip install ultralytics pyyaml

  2. Organize Your Local Data: Place your images and labels somewhere on your local drive.

  3. Set Environment Variables and Run: The src/train_general.py script automatically adapts to local paths if you set the right environment variables. Open your terminal and run:

    # Point these to the folders on your local computer where your data lives
export STAGED_AREA=/path/to/my/local/positive_data
export STAGED_NEGATIVES=/path/to/my/local/negative_data
export STAGED_CURATED=/path/to/my/local/curated_data

# Tell the script where to save the output model locally
export MODEL_DIR=./local_trained_model

# Run the training script directly
python3 src/train_general.py

This will automatically format the dataset into a temporary folder (/tmp/general_pollen_dataset), start YOLOv8 training using your local hardware, and save the final .pt weights into your chosen MODEL_DIR.
